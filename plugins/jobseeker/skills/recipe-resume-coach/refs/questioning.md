# Questioning

Graceful intake. Ask; never block indefinitely on REQUIRED lists. One question at a time when choices are enumerable; batch related factual questions when efficient.

## Principles

1. **Never fabricate** — if user doesn't know a metric, record as TBD; do not invent
2. **Never block** — if user skips a question, note gap and continue; flag at gates
3. **Specific beats generic** — ask for scope, team size, tools, scale, metrics per role
4. **Confirm metrics** — before write, user must confirm all numbers are interview-defensible

## Intake questions (all workflows)

Gather what the user already provided; ask only gaps:

| Field | Question | Required for |
|-------|----------|--------------|
| Name | "What name should appear on documents?" | Write |
| Target level | "What level are you targeting? (senior/staff/principal)" | Tailor |
| Company | "Which company is this application for?" | Tailor cover |
| JD | "Paste the full job description." | Tailor resume/cover |
| Role variant | "Which positioning fits this role?" (see disambiguation.md) | Tailor |

## Master resume questions (per role)

Repeat for each role in scope (recent 10 years minimum):

1. What did you **own** vs contribute to?
2. Team size and your scope?
3. Tools and stack?
4. Scale (requests/day, users, data volume, revenue)?
5. What **metric** improved, and by how much? (exact or range estimate)
6. What **failed** and how did you recover?
7. Any flagship project worth a dedicated bullet?

**Achievement expansion prompt pattern:**

> For [title] at [company] ([dates]), I'll ask structured questions to extract scope, metrics, and ownership. If any metric is unclear, say so — we won't invent numbers.

## Tailor flow questions

After JD is pasted:

1. Confirm role variant (if not locked)
2. "Are you ≥70–80% qualified for this role?" (Oliver guideline — warn if not)
3. Any JD requirements you **cannot** evidence? (routes to cover letter honesty or gap flag)

## Cover letter questions

1. Hiring manager name if known (else "Dear Hiring Manager")
2. One thing that drew you to this company (product, eng blog, stack)
3. Which flagship achievement best matches the JD theme?

## Metric confirmation (pre-write)

Before any write, present all quantified bullets and ask:

> Please confirm every metric below is interview-defensible. Flag any you'd change or remove.

Hard stop if user flags a metric as unverified — fix or remove before proceeding.

## AskQuestion usage

Use AskQuestion when:

- Starting state ambiguous (existing vs raw)
- Role variant unclear
- Workflow intent unclear (master vs tailor vs full)

Do not use AskQuestion for open-ended career storytelling — use conversational Q&A per role.
